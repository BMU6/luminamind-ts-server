# LuminaMind – Web Client

A self-tracking web app for people in psychiatric inpatient care. Patients record how they feel (mood, energy, sleep, concentration, irritability) and their medication, see the course of their stay in a chart, and can share it with their doctor. This is the React client. The Express/MongoDB API lives in [luminamind-ts-server](https://github.com/BMU6/luminamind-ts-server).

**Live demo:** https://luminamind-web-client.onrender.com

> The demo runs on a free hosting plan. After a period of inactivity the first request can take **about 30 seconds**. Please wait, the app is waking up.

## Features

- Registration and login for two roles: **patient** and **doctor**
- Daily check-ins with five ratings (0–5), a free-text note and the active medication
- **Home dashboard**: week chart (horizontal or vertical), click a point to read the report
- **Medication list** per patient, also editable by a linked doctor
- **Weekly AI summary** of the reports, generated by a local language model
- Doctor ↔ patient link with a one-time invite code, then a **doctor dashboard** and **chat**
- Dark and light theme, English and German

## Tech stack

React 19 · TypeScript · Vite · React Router · Tailwind CSS v4 + daisyUI 5 · Chart.js · react-i18next

The session uses a short-lived access token (sent by a small fetch interceptor that refreshes it automatically) and an httpOnly refresh cookie.

## Run it locally

You need Node.js 24 and a running instance of the [server](https://github.com/BMU6/luminamind-ts-server).

```bash
npm install
npm run dev
```

The client expects the API at `http://localhost:3000`. To use another address, create `.env.development.local` with:

```
VITE_API_URL=http://localhost:3000
```

Build for production with `npm run build`.

## Notes about the demo

- Both the demo and my local setup currently run **without database encryption**. Field-level AES-256-GCM encryption is built into the server and can be switched on, but it is off for the demo. All data is fake. Traffic to the demo goes over HTTPS.
- The access token is kept in `localStorage`. That is fine for a demo, a production setup would need a different approach.
